# I004 DSH 运行时独立更新迭代总览

状态：已完成

负责人：Goal 模式执行者

优先级：P0

更新时间：2026-08-25 21:25（Asia/Shanghai）

## 目标与业务边界

把桌面端收敛为一个不依赖 `MichengAI` 即可构建、启动、验证和继续维护的 DeepSeek Harness 桌面壳，建立可验证、可回滚的 DSH 运行时升级机制，并实际交付可供当前用户安装使用的 macOS 与 Windows 制品。

本迭代中的“不依赖 `MichengAI`”采用以下可验收定义：

- 默认构建和核心启动不访问 `github.com/MichengAI/*`，也不下载 `@michengai/*` 包。
- 默认桌面更新配置不指向 `MichengAI`；未配置独立更新源时不联网检查桌面版本。
- 已存在于用户 Profile 的 `@michengai/*` 插件不得被主动删除、降级或覆盖，但不再由核心发行闭包默认补种。
- 历史 Changelog 与 LICENSE 中的既有归属可以保留，它们不是运行或更新依赖。

本迭代必须产出个人自用的未签名安装包：当前 Apple Silicon Mac 对应 macOS arm64 的 DMG/ZIP，Windows 对应 x64 的 NSIS EXE/ZIP。制品、SHA256 和验收记录统一收口到本地 `release/personal/`；这不等于正式发行。

暂不处理正式发行：不签名、不公证、不创建 GitHub Release、不推送标签、不公开发布安装包、不设计正式更新服务器。允许使用用户有权限且不属于 `MichengAI` 的原生 Windows 构建机或 GitHub Actions 临时 artifact 完成 Windows 构建和回传。

## 已确定决策

1. 默认发行形态为 `core-only`：内置官方 `@deepseek-ai/dsh`，第三方功能插件改为显式可选目录。
2. 不硬编码新的 GitHub owner 代替 `MichengAI`；桌面更新源必须是可选配置，缺省关闭。
3. DSH 升级必须先安装和验证候选运行时，再切换当前版本；失败时保留或恢复最后可用版本。
4. 用户数据继续保存在 `~/.dsh`，本迭代不得迁移、清空或重写会话与凭据。
5. 可以调整桌面壳在官方 DSH UI 下的能力呈现；不支持的 Codex UI 专属动作应按能力检测禁用，不得用脆弱 DOM 猜测制造假成功。
6. macOS 最低交付目标为当前主机架构 arm64；Windows 最低交付目标为 x64。Intel Mac、Linux、签名、公证和自动更新 feed 不作为本次完成前提。

## 阻塞事项

正式更新源、签名证书和发布账号不是本迭代前置条件。Windows 制品必须使用原生 Windows runner；可以使用用户控制的非 `MichengAI` 仓库 Actions 临时 artifact 或用户自己的 Windows 主机。若两者均不可用，则本迭代不能标记完成，必须如实记录为阻塞。

## 验收标准

- 无 `MichengAI` 网络资源时，冻结安装、测试、运行时装配以及目标平台原生打包能够完成。
- 全新 Profile 只依赖官方 DSH 即可启动，根页面和一个静态资源返回 HTTP 200。
- 已有 Profile 中的第三方插件保持原状；core-only 启动不得擅自清理它们。
- 未配置桌面更新源时，应用不访问旧 GitHub Release，更新入口明确显示未配置或不可用。
- DSH 候选版本只有在版本一致性、入口、Profile 合成和 HTTP 健康检查全部通过后才成为 current。
- 候选安装或首次启动失败时，最后可用运行时仍可启动，用户 Profile 不受损。
- 关于页显示磁盘上的实际 DSH 版本，而不是编译期常量。
- `pnpm test`、新增升级回归测试、macOS arm64 与 Windows x64 原生打包冒烟全部通过。
- `release/personal/macos-arm64/` 中存在 DMG 与 ZIP；DMG 挂载、复制应用和首次启动验证通过，ZIP 解压启动验证通过。
- `release/personal/windows-x64/` 中存在可安装、可启动的 NSIS EXE 与 ZIP；安装、启动、退出和卸载验证通过，且卸载不删除用户 `~/.dsh` 数据。
- 四个交付文件必须来自同一 Git commit，并均有匹配的 SHA256、文件大小、来源 runner 和验证记录；不能用“等待 CI”代替实际 Windows 制品。
- CI 只构建、测试和上传临时制品，不创建标签或正式 Release。

## 已完成内容

- 默认发行闭包已改为 core-only；空白 Profile 不再补种或下载 `@michengai/*`，存量 Profile 中的第三方插件保持原状。
- 桌面发布/更新配置已改为可选 HTTPS 配置；缺省不检查网络更新，也不带固定 owner、feed 或 publish 配置。
- `package.json` 的运行时 manifest 已成为 DSH、Node 与 pnpm 的单一事实源；`runtime-lock/package-lock.json` 冻结官方运行图，装配后校验所有 `@deepseek-ai/dsh*` 包族。
- 运行时采用版本目录、原子状态文件、候选静态校验、隔离 Profile HTTP 健康检查、current/last-known-good 切换和首次真实启动回滚。
- 随包运行时只进入候选；存量安装需用户确认后才升级。当前构建没有冻结图的 DSH 版本会被明确拒绝，要求先升级桌面应用。
- CLI 参数、Profile/Bundle 边界、桌面桥接能力检测和 UI 降级已收敛；不支持动作不再通过 DOM 文本猜测伪执行。
- 手动 Windows Actions 工作流只构建未签名 x64 临时 artifact，不含标签、Release 或写权限；macOS/Windows 原生制品冒烟脚本已补齐。
- 固定 Node `24.19.0`、pnpm `11.22.0` 下，`pnpm run check`、独立性闸门和 177 项测试全部通过；首次打包冒烟修复冻结图遗漏非可选 peer，Windows run #1 修复 `$HOME` 变量冲突，run #2 修复空 `$LASTEXITCODE` 误判，run #3 改为只按 `DSH_SMOKE_READY` 识别最终服务。
