# 桌面启动器架构基线

更新时间：2026-08-25 19:25（Asia/Shanghai）

## 架构目标

桌面层仅负责 Windows x64、macOS arm64/x64 与 Linux x64 的分发、运行时、子进程、窗口和生命周期；DSH 继续提供 Web UI、Agent、会话和业务能力。

## 运行链路

`Electron 主进程 → 内置 Node 运行时 → DSH 生产入口 → 127.0.0.1 随机端口 → BrowserWindow`

## 运行闭包

- Node 使用官方 Node 24 固定补丁版本并按 Windows x64、macOS arm64/x64、Linux x64 校验 SHA256。
- DSH 运行时从冻结的 `runtime-lock/package-lock.json` 用 `npm ci` 装配 `@deepseek-ai/dsh@0.1.1-rc.2`，归档为 `runtime-dsh.tgz`；装配后校验包身份、入口、启动 peer 和全部 `@deepseek-ai/dsh*` 版本。
- Node 固定 `24.19.0`，启动器固定 pnpm `11.22.0`；三者由 `package.json.config.runtimeManifest` 单点声明，升级命令同步生成 runtime lock 并报告补丁适配状态。
- 随包归档首启只安装为版本化候选。macOS 可变运行时位于 userData；Windows 优先使用可写安装目录旁的运行时根，失败时回退 userData。社区插件在线更新仍写入 `~/.dsh/profiles/web`。卸载不得删除 `~/.dsh`。
- 运行时文件保留真实文件布局，不将 DSH 依赖临时解压到 ASAR 外。

## 启动与导航

1. Electron 获取单实例锁并展示本地启动页。
2. 以 `dsh web --port 0 --no-open` 启动 DSH；桌面窗口承载界面，禁止官方 Web 再打开系统浏览器。
3. 缓冲标准输出，识别 `dsh web:` 就绪行。
4. 仅接受 `http:`、`127.0.0.1` 与合法端口的 URL。
5. HTTP 健康检查成功后才加载 BrowserWindow。
6. 失败、超时或异常退出时显示中文错误和脱敏日志位置。

## 安全与生命周期

- Electron 使用 `nodeIntegration: false`、`contextIsolation: true`。
- 禁止任意 Electron IPC 暴露给 DSH 页面。
- 拒绝 `file:`、`javascript:`、`data:` 及非 loopback 导航；外部链接交给系统浏览器。
- 正常关闭通过 Node 引导脚本和父子进程控制通道触发 DSH 既有关闭逻辑。
- 超时只处理启动器创建的 PID；不得全局结束 `node.exe`。
- 不删除 `%USERPROFILE%\.dsh`，日志不得记录敏感数据。
- 卸载只结束 `DSH Codex Desktop.exe` 及其子进程，必须排除 `Uninstall*`，不得按安装目录无差别杀进程；完成后删除 `%APPDATA%\\DSH Codex Desktop` 与托盘 `NotifyIconSettings` 残留。
- Linux 窗口关闭即退出；CI 冒烟检查仅为 GitHub Runner 的未安装目录传递 `--no-sandbox`，发布应用保持默认沙箱策略。
- 桌面 exe 更新只走托盘「检查桌面端更新」，源是 GitHub Releases 的 latest.yml；启动不检查、不自动下载。插件更新仍走关于页，二者不得混用。


## 社区插件随包与在线安装

- 六个功能插件与 dshmarket 在 `prepare-runtime` 写入 `runtime-plugins/store.tgz`，打包成单个压缩包，避免安装器解压上万个小文件。
- 首次启动用离线 store 把社区插件补种到 `~/.dsh/profiles/web`。
- 已装 `@michengai/dsh-codex-suite` 时拆成六个独立功能插件；dshmarket 单独补种；已有同名包时跳过，不覆盖用户在线安装的版本。
- 解析顺序是安装目录优先，因此社区包不得进入官方运行时 `node_modules`。
- 随包 `resources/node` 同时提供 `node` 与 `pnpm`；DSH 子进程 PATH 前置该目录，code-ui 与 dshmarket 的 CLI 安装路径才能工作。
- 补种失败只写 `plugin-seed.log`，不阻断 DSH 启动。

## 官方运行时预装

- `prepare-runtime` 把 `@deepseek-ai/dsh` 和启动必需 peer 预装后打成 `runtime-dsh.tgz`，首启再解到安装目录。
- 官方 DSH 家族目标版本为 `0.1.1-rc.2`，以冻结 lock 装配并通过完整依赖族一致性校验；未知新版本不会套用旧补丁，也不能绕过冻结图在线激活。
- 状态文件表达 `staging`、`current`、`lastKnownGood`、`available` 和待确认激活。候选完成静态验证和隔离 Profile loopback HTTP 健康检查后才能切换；首次真实启动未确认或失败时回滚 last-known-good。
- 官方包不得写入 Web profile。关于页、插件市场若更新 `@deepseek-ai/dsh*`，桌面端改写 `dsh-runtime` 整组版本，不把官方包装进用户 profile。
- 官方运行时只在关于页手动点更新时写 pending；随包候选高于 current 时需要用户确认。当前构建无对应冻结图的版本会提示先升级桌面应用。
- 安装包会变大，换来的是新用户首启不再解析、下载、链接整棵官方依赖。

## I004 个人制品边界

- 最低交付矩阵为当前主机对应的 macOS arm64 DMG/ZIP，以及原生 Windows x64 runner 生成的 NSIS EXE/ZIP。
- `release/personal/` 是本地、Git 忽略的个人交付目录，不是更新 feed 或正式发布目录；四个制品必须来自同一 Git commit，并带可复核的 SHA256、大小、构建来源和安装启动记录。
- DMG 需要验证挂载、复制应用、启动、loopback 健康检查和退出；macOS ZIP 需要验证解压后的同等启动路径。
- Windows NSIS 需要验证安装、启动、退出、卸载和用户 Profile 哨兵保留；Windows ZIP 需要验证解压后的启动路径。
- 未签名包可以触发 Gatekeeper 或 SmartScreen。文档只能给出针对本应用的个人允许步骤，不得要求用户全局关闭操作系统安全机制。
- Windows 可以使用用户有权限且不属于 `MichengAI` 的 GitHub Actions 临时 artifact；不得创建标签、GitHub Release 或公开下载页。
